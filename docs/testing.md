# 手動確認手順

手動での動作確認手順をここにまとめる。

自動テストは [`testing-guide.md`](testing-guide.md) を参照する。

## 前提

- Node.js 22.13.0 以上（ESLint 10 の要求）
- 初回のみ `npm install`

## 1. コマンドラインでの確認

コードを書き換えたら、まずこの3つを通す。PRを出す前にも実行する。

```bash
npm run compile        # 全共有パッケージと拡張の型が通るか
npm run lint           # 書き方の規約に反していないか
npm run format:check   # 整形済みか。崩れていれば npm run format で直す
```

いずれもエラーが無ければ何も表示されずに終了する。

### ESLintルールの確認

`apps/vscode-extension/src/ai/` から `vscode` を import できないルールが効いていることを確認する場合は、一時的に次のファイルを作って `npm run lint` を実行する。

```ts
// apps/vscode-extension/src/ai/_probe.ts
import * as vscode from "vscode";
export const probe = vscode.version;
```

`no-restricted-imports` のエラーが出れば正常。確認後はファイルを削除する。

## 2. 拡張の動作確認

1. VS Code でこのリポジトリを開く
2. 右下に推奨拡張機能のインストールを促されたら入れる（ESLint / Prettier）
3. `F5` を押す
4. 別ウィンドウが開く。タイトルバーに `[拡張機能開発ホスト]` と表示されていれば起動成功
5. 開発ホスト側のウィンドウで適当なファイルを開く
6. コードを選択して `Ctrl + Shift + J`（mac は `Cmd + Shift + J`）
7. **元のウィンドウに戻り、「デバッグ コンソール」パネルを確認する**

### ログの出る場所

出力先は**「デバッグ コンソール」であり、ターミナルではない**。ここが最もつまずきやすい。

開発ホストでは他の拡張も同時に動くため、無関係なログが多く混ざる。自分のコードの出力かどうかは、`console.log` した内容と一致するかで判断する。

## 4. ターミナル選択の確認（選択/05 #16）

クリップボード経由でターミナルの選択範囲を取得する経路。エディタ選択とは別のコマンド（`gakushuSochi.askTerminalSelection`）が `when: terminalFocus` で登録されている。

`package.json` を変更した場合は、デバッグを停止して `F5` で起動し直す。リロードだけでは `contributes` の変更が反映されないことがある。

### 手順

1. 事前に何か適当な文章をコピーしておく（クリップボードの復元を確認するため）
2. 開発ホストのターミナルで文字列を選択し `Ctrl + Shift + J`
3. 確認ダイアログの内容を見て「送る」を押す
4. どこかに `Ctrl + V` で貼り付ける

### 確認項目

| #   | 操作                                             | 期待する結果                                              | 結果     |
| --- | ------------------------------------------------ | --------------------------------------------------------- | -------- |
| 1   | ターミナルで選択して実行                         | 確認ダイアログに選択内容が表示される                      | 確認済み |
| 2   | 「送る」を押す                                   | デバッグコンソールに全文が出る                            | 確認済み |
| 3   | 実行後に `Ctrl + V`                              | **手順1でコピーした内容が出る**。ターミナルの内容は出ない | 確認済み |
| 4   | 何も選択せずに実行                               | 「ターミナルでテキストを選択してください」                | 未確認   |
| 5   | 4の直後に `Ctrl + V`                             | 手順1の内容のまま。無関係な内容が送られていない           | 未確認   |
| 6   | ターミナルの内容をコピー → 同じ箇所を選択 → 実行 | 正しく取得できる                                          | 未確認   |

3が最重要。ここが壊れていると「この拡張を使うとコピーした内容が消える」という体験になる。

5は安全性の確認。何も選択せずに実行したとき、以前ユーザーがコピーした無関係な内容（トークンやパスワードを含み得る）をAIへ送ってしまわないことを見ている。

6は選択なし判定の方式を検証する項目。実行前後のクリップボードを比較する方式だと、選択内容が既にクリップボードにある場合に「変化なし = 選択されていない」と誤判定する。実装では毎回異なる目印を書き込んでから読み直す方式を採っており、この誤判定は起きない。

### 3で「ターミナルの内容が出てこない」のは正常

取得できたかどうかは2（デバッグコンソール）で確認する。3で見ているのはクリップボードを壊していないかであり、ターミナルの内容が貼り付けられたら不具合である。

## 5. クリップボードの確認（選択/06 #19）

VS Code の外（ブラウザ、Slack、PDF、他のアプリ）でコピーしたテキストを取り込む経路。

ターミナル版（4）と違い、**コピーは拡張ではなくユーザーが行う**。VS Code から他アプリにコピーを命令することはできないため。したがって目印（sentinel）による「選択されていない」判定は使えず、クリップボードを読むだけになる。

**キーは `Ctrl + Alt + J`。** `when` を付けていないので、フォーカスがどこにあっても動く。

`Ctrl + Shift + J` を使わないのは、そちらが `editorTextFocus` と `terminalFocus` で使用済みのため。他アプリから VS Code に戻った直後はフォーカス位置が予測できず、同じキーにすると別のコマンドが誤って動く。

設計の背景は [input-sources.md](input-sources.md) を参照。

### 手順

1. ブラウザなど VS Code 以外のアプリで文章を選択し `Ctrl + C`
2. 開発ホストに切り替える
3. `Ctrl + Alt + J` を押す（またはコマンドパレットから `Gakushu Sochi: Ask Clipboard`）
4. 確認ダイアログの内容を見て「送る」を押す
5. どこかに `Ctrl + V` で貼り付ける

### 確認項目

| #   | 操作                                      | 期待する結果                           | 結果   |
| --- | ----------------------------------------- | -------------------------------------- | ------ |
| 1   | コマンドパレットで `Gakushu Sochi` を検索 | `Ask Clipboard` が候補に出る           | 未確認 |
| 1b  | 他アプリでコピーしてから `Ctrl + Alt + J` | 確認ダイアログが出る                   | 未確認 |
| 2   | 他アプリでコピーしてから実行              | 確認ダイアログにその内容が表示される   | 未確認 |
| 3   | 「送る」を押す                            | デバッグコンソールに全文が出る         | 未確認 |
| 4   | ダイアログで「キャンセル」または `Esc`    | 何も出力されない                       | 未確認 |
| 5   | 実行後に `Ctrl + V`                       | コピーした内容がそのまま貼れる         | 未確認 |
| 6   | 複数行をコピーして実行                    | 改行が保持されて出力される             | 未確認 |
| 7   | 空白だけをコピーして実行                  | 「クリップボードが空です」と案内が出る | 未確認 |

4は安全性の確認。エディタの外から来たテキストには意図しない情報が混ざり得るため、確認せずに送信できてはいけない。

5は、このコマンドがクリップボードを書き換えていないことの確認。読むだけなので本来変化しないが、4と違い復元処理を持たないので実際に確かめておく。

7は空文字だけでなく空白や改行のみの場合も案内が出る。空にする手順が分かりにくいときは、エディタで空行を1つ選択してコピーすればよい。

### 「昔コピーした内容」が送られ得るのは仕様

不具合ではなく、この方式の限界である。クリップボードには「いつ、どこからコピーされたか」の情報がない。数時間前にコピーしたパスワードが残っていても、拡張からは区別できない。

4のターミナル版には目印による検出があるが、こちらには無い。**確認ダイアログが唯一の防御になる**ので、実装から外してはいけない。

## 6. うまくいかないとき

| 症状                             | 原因と対処                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------- |
| 何も出力されない                 | ターミナルを見ている可能性がある。「デバッグ コンソール」パネルに切り替える           |
| ショートカットが反応しない       | エディタ本体にフォーカスが必要。ターミナルやサイドバーにフォーカスがあると発火しない  |
| コードを直したのに反映されない   | `tsc -watch` は自動で再ビルドするが、開発ホスト側は `Ctrl + R` でリロードが必要       |
| `F5` でビルドが走らない          | `.vscode/tasks.json` の watch タスクが動いているか確認する                            |
| `npm install` で EBADENGINE 警告 | Node が 22.13.0 未満。22.13 以上か 24 LTS に上げる                                    |
| ターミナルで押しても反応しない   | `when: terminalFocus` のため、ターミナルにフォーカスが必要                            |
| 貼り付けたら元の内容が消えていた | クリップボードの復元が失敗している。不具合として報告する                              |
| `Ask Clipboard` が候補に出ない   | `package.json` の変更はリロードでは反映されない。デバッグを停止して `F5` で起動し直す |
| 送った覚えのない内容が表示される | クリップボードに古い内容が残っている。「キャンセル」で送信を止め、コピーし直す        |

`console.log` の行にブレークポイントを置けば、変数の中身を止めて確認できる。
