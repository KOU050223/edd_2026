# 手動確認手順

手動での動作確認手順をここにまとめる。

自動テストは [`testing-guide.md`](testing-guide.md) を参照する。

## 前提

- Node.js は `.node-version` の 24.20.0（ESLint 10 は 22.13.0 以上を要求する）
- 初回のみ `npm install`

## 1. コマンドラインでの確認

コードを書き換えたら、まずこの3つを通す。PRを出す前にも実行する。

```bash
npm run compile        # 全共有パッケージと拡張の型が通るか
npm run lint           # 書き方の規約に反していないか
npm run format:check   # 整形済みか。崩れていれば npm run format で直す
```

いずれもエラーが無ければ何も表示されずに終了する。

### ESLintルールの確認

`apps/vscode-extension/src/ai/` から `vscode` を import できないルールが効いていることを確認する場合は、一時的に次のファイルを作って `npm run lint` を実行する。

```ts
// apps/vscode-extension/src/ai/_probe.ts
import * as vscode from "vscode";
export const probe = vscode.version;
```

`no-restricted-imports` のエラーが出れば正常。確認後はファイルを削除する。

## 2. 拡張の動作確認

1. VS Code でこのリポジトリを開く
2. 右下に推奨拡張機能のインストールを促されたら入れる（ESLint / Prettier）
3. `F5` を押す
4. 別ウィンドウが開く。タイトルバーに `[拡張機能開発ホスト]` と表示されていれば起動成功
5. 開発ホスト側のウィンドウで適当なファイルを開く
6. コードを選択して `Ctrl + Shift + J`（mac は `Cmd + Shift + J`）
7. **元のウィンドウに戻り、「デバッグ コンソール」パネルを確認する**

### ログの出る場所

出力先は**「デバッグ コンソール」であり、ターミナルではない**。ここが最もつまずきやすい。

開発ホストでは他の拡張も同時に動くため、無関係なログが多く混ざる。自分のコードの出力かどうかは、`console.log` した内容と一致するかで判断する。

## 4. ターミナル選択の確認（選択/05 #16）

クリップボード経由でターミナルの選択範囲を取得する経路。エディタ選択とは別のコマンド（`gakushuSochi.askTerminalSelection`）が `when: terminalFocus` で登録されている。

`package.json` を変更した場合は、デバッグを停止して `F5` で起動し直す。リロードだけでは `contributes` の変更が反映されないことがある。

### 手順

1. 事前に何か適当な文章をコピーしておく（クリップボードの復元を確認するため）
2. 開発ホストのターミナルで文字列を選択し `Ctrl + Shift + J`
3. 確認ダイアログの内容を見て「送る」を押す
4. どこかに `Ctrl + V` で貼り付ける

### 確認項目

| #   | 操作                                             | 期待する結果                                              | 結果     |
| --- | ------------------------------------------------ | --------------------------------------------------------- | -------- |
| 1   | ターミナルで選択して実行                         | 確認ダイアログに選択内容が表示される                      | 確認済み |
| 2   | 「送る」を押す                                   | デバッグコンソールに全文が出る                            | 確認済み |
| 3   | 実行後に `Ctrl + V`                              | **手順1でコピーした内容が出る**。ターミナルの内容は出ない | 確認済み |
| 4   | 何も選択せずに実行                               | 「ターミナルでテキストを選択してください」                | 未確認   |
| 5   | 4の直後に `Ctrl + V`                             | 手順1の内容のまま。無関係な内容が送られていない           | 未確認   |
| 6   | ターミナルの内容をコピー → 同じ箇所を選択 → 実行 | 正しく取得できる                                          | 未確認   |

3が最重要。ここが壊れていると「この拡張を使うとコピーした内容が消える」という体験になる。

5は安全性の確認。何も選択せずに実行したとき、以前ユーザーがコピーした無関係な内容（トークンやパスワードを含み得る）をAIへ送ってしまわないことを見ている。

6は選択なし判定の方式を検証する項目。実行前後のクリップボードを比較する方式だと、選択内容が既にクリップボードにある場合に「変化なし = 選択されていない」と誤判定する。実装では毎回異なる目印を書き込んでから読み直す方式を採っており、この誤判定は起きない。

### 3で「ターミナルの内容が出てこない」のは正常

取得できたかどうかは2（デバッグコンソール）で確認する。3で見ているのはクリップボードを壊していないかであり、ターミナルの内容が貼り付けられたら不具合である。

## 5. クリップボードの確認（選択/06 #19）

VS Code の外（ブラウザ、Slack、PDF、他のアプリ）でコピーしたテキストを取り込む経路。

ターミナル版（4）と違い、**コピーは拡張ではなくユーザーが行う**。VS Code から他アプリにコピーを命令することはできないため。したがって目印（sentinel）による「選択されていない」判定は使えず、クリップボードを読むだけになる。

**キーは `Ctrl + Alt + J`。** `when` を付けていないので、フォーカスがどこにあっても動く。

`Ctrl + Shift + J` を使わないのは、そちらが `editorTextFocus` と `terminalFocus` で使用済みのため。他アプリから VS Code に戻った直後はフォーカス位置が予測できず、同じキーにすると別のコマンドが誤って動く。

設計の背景は [input-sources.md](input-sources.md) を参照。

### 手順

1. ブラウザなど VS Code 以外のアプリで文章を選択し `Ctrl + C`
2. 開発ホストに切り替える
3. `Ctrl + Alt + J` を押す（またはコマンドパレットから `Gakushu Sochi: Ask Clipboard`）
4. 確認ダイアログの内容を見て「送る」を押す
5. どこかに `Ctrl + V` で貼り付ける

### 確認項目

| #   | 操作                                      | 期待する結果                           | 結果   |
| --- | ----------------------------------------- | -------------------------------------- | ------ |
| 1   | コマンドパレットで `Gakushu Sochi` を検索 | `Ask Clipboard` が候補に出る           | 未確認 |
| 1b  | 他アプリでコピーしてから `Ctrl + Alt + J` | 確認ダイアログが出る                   | 未確認 |
| 2   | 他アプリでコピーしてから実行              | 確認ダイアログにその内容が表示される   | 未確認 |
| 3   | 「送る」を押す                            | デバッグコンソールに全文が出る         | 未確認 |
| 4   | ダイアログで「キャンセル」または `Esc`    | 何も出力されない                       | 未確認 |
| 5   | 実行後に `Ctrl + V`                       | コピーした内容がそのまま貼れる         | 未確認 |
| 6   | 複数行をコピーして実行                    | 改行が保持されて出力される             | 未確認 |
| 7   | 空白だけをコピーして実行                  | 「クリップボードが空です」と案内が出る | 未確認 |

4は安全性の確認。エディタの外から来たテキストには意図しない情報が混ざり得るため、確認せずに送信できてはいけない。

5は、このコマンドがクリップボードを書き換えていないことの確認。読むだけなので本来変化しないが、4と違い復元処理を持たないので実際に確かめておく。

7は空文字だけでなく空白や改行のみの場合も案内が出る。空にする手順が分かりにくいときは、エディタで空行を1つ選択してコピーすればよい。

### 「昔コピーした内容」が送られ得るのは仕様

不具合ではなく、この方式の限界である。クリップボードには「いつ、どこからコピーされたか」の情報がない。数時間前にコピーしたパスワードが残っていても、拡張からは区別できない。

4のターミナル版には目印による検出があるが、こちらには無い。**確認ダイアログが唯一の防御になる**ので、実装から外してはいけない。

## 6. 送信の同意の確認（基盤/07 #119）

この拡張が外へ何かを送る前に、何が誰へ送られるかを提示して同意を取る経路。
送信先ごとの内容は [data-privacy.md](data-privacy.md) の「何が誰へ送られるか」が正本で、
ダイアログの文面は `packages/domain/src/consent.ts` がそれを要約している。

同意は `globalState` に記録される。**設定には出ない**ので、設定画面を探しても見つからないのが正しい。
ワークスペース設定から同意を偽装されないようにするため（RULE-006）。

同意は一度きりの合意で、ターミナル／クリップボードの確認ダイアログ（4・5）とは別物。
同意済みでも、あちらの本文プレビューは毎回出る。

### 手順

同意の記録を消してから始める。開発ホストのコマンドパレットで
`Gakushu Sochi: 送信内容の同意を取り消す` を実行すると未同意の状態に戻る。

1. エディタでコードを選択し `Ctrl + Shift + J`
2. 同意ダイアログの文面を読み、「同意しない」を押す
3. もう一度 `Ctrl + Shift + J` を押し、今度は「同意して続ける」を押す
4. さらにもう一度 `Ctrl + Shift + J` を押す
5. コマンドパレットから `Gakushu Sochi: 送信内容の同意を確認する`
6. `Gakushu Sochi: 送信内容の同意を取り消す` を実行してから `Ctrl + Shift + J`

### 確認項目

| #   | 操作                                          | 期待する結果                                                                                                                                       | 結果   |
| --- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| 1   | 未同意で `Ctrl + Shift + J`                   | 同意ダイアログが出る。Chat は開かない                                                                                                              | 未確認 |
| 2   | 文面を読む                                    | Copilot と学習記録サーバーが別々に書かれ、送るものと保存されるものが分かる。選択範囲だけでなく、周辺コードと参照先の定義コードも送ると書かれている | 未確認 |
| 3   | 「同意しない」を押す                          | Chat が開かない。出力パネルにコードが出ない                                                                                                        | 未確認 |
| 4   | `Esc` でダイアログを閉じる                    | 3と同じ。閉じただけでは同意にならない                                                                                                              | 未確認 |
| 5   | 「同意して続ける」を押す                      | Chat が開き、選択した文脈が引き継がれる                                                                                                            | 未確認 |
| 6   | もう一度 `Ctrl + Shift + J`                   | ダイアログは出ず、そのまま Chat が開く                                                                                                             | 未確認 |
| 7   | 開発ホストを再起動して `Ctrl + Shift + J`     | ダイアログは出ない（記録が残っている）                                                                                                             | 未確認 |
| 8   | `送信内容の同意を確認する`                    | 同じ文面と「現在、送信に同意しています」が出る                                                                                                     | 未確認 |
| 9   | 8のダイアログで「同意を取り消す」             | 「取り消しました」と出る                                                                                                                           | 未確認 |
| 10  | 取り消し後に `Ctrl + Shift + J`               | 再び同意ダイアログが出る。同意するまで Chat は開かない                                                                                             | 未確認 |
| 11  | 同意済みで `Ctrl + Alt + J`（クリップボード） | 同意ダイアログは出ず、本文プレビューの確認だけが出る                                                                                               | 未確認 |
| 12  | 未同意で `Ctrl + Alt + J`                     | 同意ダイアログが先に出る。本文プレビューまで進まない                                                                                               | 未確認 |

3と4が要。**同意しなければ何も外へ出ない**ことがこの機能の目的であり、
ここが崩れていたら他の項目が通っていても不合格。

7は記録が `globalState` に残っていることの確認。毎回聞かれるなら保存に失敗している。
その場合は出力パネル「Gakushu Sochi」に記録失敗のログが出ているはずなので、そちらを見る。

12は順序の確認。同意より先に本文プレビューが出ると、未同意の段階で内容を
送る前提の画面を見せることになる。

### 同意を取り消しても、送信済みのデータは消えない

取り消しで止まるのは**これから送るもの**だけである。すでに Copilot や
学習記録サーバーへ渡ったものは対象外で、削除は別の課題（#79）が持つ。
ダイアログの文面にもそう書いてあるので、書かれていなければ実装側の不備である。

### Desktop / Web の同意（基盤/11 #174）

同じ文面・同じ版の同意を、Desktop と Web にも展開したもの。記録先はクライアントごとに違う
（data-privacy.md「同意を取るまで送らない」が正本）。

**Desktop**: 同意の記録は `userData` 直下の `consent.json`。消すと未同意に戻る。

| #   | 操作                                          | 期待する結果                                         |
| --- | --------------------------------------------- | ---------------------------------------------------- |
| 1   | 未同意で質問を送る                            | 同意ダイアログが出る。「同意しない」なら送信されない |
| 2   | 「同意して続ける」を押す                      | そのまま回答が返る                                   |
| 3   | 設定画面の「送信の同意」→「内容を確認」       | 同じ文面と「現在、送信に同意しています」が出る       |
| 4   | 3のダイアログで「同意を取り消す」→ 質問を送る | 再び同意ダイアログが出る                             |

**Web**: 同意の記録は Workers KV の `consent:{sub}`。取り消すには設定画面から。

| #   | 操作                                  | 期待する結果                                       |
| --- | ------------------------------------- | -------------------------------------------------- |
| 1   | 未同意で設定を保存する                | 「送信の同意がありません」と表示され、保存されない |

## 7. BYOK の確認（AI/04 #55）

拡張が `vscode.lm` を通さず、利用者自身の API キーで直接 AI 提供元を呼ぶ経路。
API キーは VS Code の SecretStorage にだけ保存され、設定ファイルや
運営側のサーバーへは送られない。

`package.json` を変更した場合は、デバッグを停止して `F5` で起動し直す。

### 手順

1. コマンドパレットから `Gakushu Sochi: BYOK の API キーを設定する` を実行し、
   提供元（anthropic / openai）を選んでキーを入力する
2. 設定で `gakushuSochi.ai.provider` を `byok` にする
   （`byok.vendor` がキーを登録した提供元と一致していること）
3. エディタでコードを選択して `Ctrl + Shift + J`
4. Chat に回答が返ることを確認する
5. `gakushuSochi.ai.provider` を `vscode-lm` に戻してもう一度実行する

### 確認項目

| #   | 操作                                                   | 期待する結果                                           | 結果   |
| --- | ------------------------------------------------------ | ------------------------------------------------------ | ------ |
| 1   | キー未設定のまま `byok` を選んで質問する               | 「API キーが未設定」と案内が出る。送信は行われない     | 未確認 |
| 2   | 手順1〜4を実行する                                     | BYOK 経路で回答が返る。出力パネルに生の応答が出る      | 未確認 |
| 3   | 手順5で `vscode-lm` へ戻して質問する                   | Copilot 経路で回答が返る（切り替えが即時に効く）       | 未確認 |
| 4   | 間違ったキーを設定して質問する                         | `auth-failed` と案内が出る。設定し直しの手順が示される | 未確認 |
| 5   | `byok.baseUrl` に平文 http の外部 URL を書いて質問する | 送信されず「URL が安全ではありません」と出る           | 未確認 |
| 6   | `Gakushu Sochi: BYOK の API キーを削除する` を実行     | 以降の質問は 1 と同じ未設定の案内に戻る                | 未確認 |

2 のとき、設定画面（`settings.json`）にキーが**書き込まれていないこと**もあわせて見る。
キーは SecretStorage に入り、設定項目として存在しないのが正しい（RULE-006）。

5 は安全性の確認。ワークスペース設定でも `gakushuSochi.byok.*` は
上書きできない（scope が machine）ので、利用者設定でのみ試すこと。

## 8. うまくいかないとき

| 症状                             | 原因と対処                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------- |
| 何も出力されない                 | ターミナルを見ている可能性がある。「デバッグ コンソール」パネルに切り替える           |
| ショートカットが反応しない       | エディタ本体にフォーカスが必要。ターミナルやサイドバーにフォーカスがあると発火しない  |
| コードを直したのに反映されない   | `tsc -watch` は自動で再ビルドするが、開発ホスト側は `Ctrl + R` でリロードが必要       |
| `F5` でビルドが走らない          | `.vscode/tasks.json` の watch タスクが動いているか確認する                            |
| `npm install` で EBADENGINE 警告 | Node が古い。`.node-version` の 24.20.0 に合わせる                                    |
| ターミナルで押しても反応しない   | `when: terminalFocus` のため、ターミナルにフォーカスが必要                            |
| 貼り付けたら元の内容が消えていた | クリップボードの復元が失敗している。不具合として報告する                              |
| `Ask Clipboard` が候補に出ない   | `package.json` の変更はリロードでは反映されない。デバッグを停止して `F5` で起動し直す |
| 送った覚えのない内容が表示される | クリップボードに古い内容が残っている。「キャンセル」で送信を止め、コピーし直す        |

`console.log` の行にブレークポイントを置けば、変数の中身を止めて確認できる。

## 9. Desktop パッケージ版の手動確認（基盤/14 #279）

`npm run dev` と違い、配布物と同じ経路（`app://` スキーム・asar・Fuses）で動かす確認。
リリース前に実機で行う。

```bash
cd apps/desktop
npm run package                       # dist/ に DMG / NSIS を生成
node scripts/check-package.mjs        # asar の中身・Fuses・署名を機械検査
```

### 手順

1. `dist/` の DMG（Windows は NSIS インストーラー）からインストールして起動する
2. メニューバー / タスクトレイのアイコンからウィンドウを開く
3. 任意のアプリで文字列を選択し、設定したショートカット（既定 `Cmd/Ctrl+Shift+K`）を押す
4. 質問を送り、回答がストリーミングで返ることを確認する
5. 生成中に「停止」ボタンを押す
6. 設定から OAuth ログインを行い、アプリを再起動する
7. 「履歴のインポート」を実行する
8. ターミナルで `ELECTRON_RUN_AS_NODE=1` を付けて実行ファイルを起動する

### 確認項目

| #   | 操作                                             | 期待する結果                                                                     |
| --- | ------------------------------------------------ | -------------------------------------------------------------------------------- |
| 1   | インストールして起動                             | トレイにアイコンが出る。画面が `app://` から表示される（白画面・404 にならない） |
| 2   | 他アプリで選択してショートカット                 | 選択テキストを載せたウィンドウが開く                                             |
| 3   | 質問して `Cmd/Ctrl+Enter`                        | 回答が流れる                                                                     |
| 4   | 生成中に「停止」                                 | 「回答を停止しました」の通知。エラー表示ではない                                 |
| 5   | 質問の前に何かをコピーしておき、実行後に貼り付け | コピーした内容が残っている（クリップボードが復元される）                         |
| 6   | OAuth ログイン                                   | ブラウザで認可後、アプリがログイン状態になる                                     |
| 7   | ログイン後にアプリを再起動                       | ログイン状態が引き継がれる                                                       |
| 8   | 履歴のインポート                                 | 分析 → プレビュー → 適用まで進む                                                 |
| 9   | `ELECTRON_RUN_AS_NODE=1` で起動                  | **Node として動かず**、普通にアプリが起動するか即終了する（Fuses で無効化済み）  |

### ログイン状態の引き継ぎについて

API トークンは OS の資格情報ストアに safeStorage 鍵で暗号化して置く。
**開発ビルドは adhoc 署名のためビルドのたびに署名が変わり**、Keychain が
「別アプリからの鍵へのアクセス」と見なして確認ダイアログを出すことがある。
これは仕様であり、正式なコード署名と公証は #278 で入れる。確認が出ても許可すればよい。

## Web の Claude Code 履歴（#157）

前提: ローカル API に migration `0023_import_creation_tokens.sql` まで適用し、Web と API を起動する。
実 AI を使う確認には設定済みの Managed AI と利用枠が必要。通常の自動テストは AI を偽物に差し替える。

1. Chrome / Edge でログインし、「Claude Code 履歴」から履歴フォルダを選ぶ。
   Windows は選択ダイアログのアドレス欄に `%USERPROFILE%\.claude\projects`、
   macOS は `⌘⇧G` に `~/.claude/projects` を入力する。Git のフォルダは選ばない。
   プロジェクト別フォルダや変更した保存先も選択できることを確認する。
2. プロジェクト・質問件数・質問カード・前処理の警告を確認する。
   メール・資格情報・パスがマスクされ、ツール出力やシステム文が質問になっていないことを見る。
   処理中にキャンセルし、保存済み分が残り、成功完了と表示されないことを確認する。
3. ブラウザを終了して開き直す。素材が残り、マップ側でフォルダを選び直さず利用できることを見る。
   別アカウントでは素材・再開データが出ないこと、サイトデータ消去後は再取り込みの案内が出ることを見る。
4. 履歴を追記・編集・切り詰めて「履歴を更新」。更新日時が同じ編集や過去日時の追加も取り込まれ、
   未変更の再取り込みで件数が増えないことを確認する。権限を失効させた場合は再許可・再選択を案内することを見る。
5. 履歴管理でプロジェクト別の件数・質問カード・検索・ページ切り替えを確認する。
   中断通知・パスだけの発話が出ないことを見る。固定の言語別マップと自分のマップで
   「取り込んだ質問を確認する」を開き、プロジェクトと送信する質問を確認する。
   期間入力がなく、同意なしでは外部送信しないことを見る。
6. 「名前が一致する概念を探す」、または同意して「AI で関連する概念を探す」を押す。
   関連する概念・質問件数・根拠の質問を確認する。誤った概念を除外して「マップに反映」。
   該当ノードが選択され、「履歴あり」の件数とマップ集計が更新されることを見る。
   学習中・確認済みのノードでも履歴が表示され、理解度と確認済み件数は増えないことを見る。
   再読み込みして画面を開いた後も、結果と除外設定が自動で読み込まれることを見る。
7. 呼び出し上限・429・通信失敗で停止し、解析済み分を反映する。ブラウザを開き直し、同じマップ・プロジェクトで
   結果が自動表示され、「続きを解析する」で既処理分をやり直さず続きを解析できることを見る。
8. マップの説明・理解項目を一部変更、Concept を追加・削除する。変更分と新規 Concept は再解析対象になり、
   未変更分は残ることを見る。古いプレビューの適用は拒否され、同じ ID の異なる定義は保留されることを見る。
9. 再送・別の反映・別マップで同じ ID を参照した反映でも二重計上しないことを確認する。
   応答を失った反映は「反映を再確認」で再送し、定義が変わった場合は「未反映の候補からやり直す」を使う。
10. 各反映を Undo し、その回に追加した分だけ消えることを見る。別 Concept への追加や以前の観測は残る。
    最後にプロジェクト別・全件のローカル削除を行い、素材と関連進捗だけ消え、反映済み観測は残ることを見る。

## Web のリポジトリからのマップ（#249）

自動テストは判断（`apps/web/src/client/repo-maps.ts`）と API（`apps/api/src/routes/repo-maps*.test.ts`）まで。
**画面は jsdom が無く自動テストできない**ので、次を手で確かめる。Web のプレビューは本番の API（`API_ORIGIN`）を
使うので、確認で作る下書き・マップは本番に残る（確認したら消す）。

### 準備

- 本番の API に `GITHUB_TOKEN` が登録されていること（`apps/api/README.md`）
- ログインして、マップの生成の同意（設定の「学習データ」）を取り消しておくと、同意の流れも確かめられる

### 確認項目

1. `/maps` →「GitHub のリポジトリからマップを作る」→ `github.com/KOU050223/edd_2026` を入れて確認する
   （**今月の枠が減らない**）。読む時点の commit、ファイル数、読まないもの（理由つき）が出る
2. モノレポの案内と対象フォルダが出る（`packages/domain` などの共有が既定で選ばれる）。
   `github.com/owner`（形が違う）・存在しないリポジトリで、API の文面（400・404）が出る
3. 参考にしてほしいファイルに存在しないパスを入れて「下書きを作る」→ 400 の文面。枠は減らない
4. 下書きを作る → 今月の枠が 1 減る → 下書きの画面へ移る
5. 「材料を読んで候補を作る」→ 同意の確認（初回）→ 候補が出る。外部呼び出しの上限で止まったら
   「続きを読んでいます」と出て、自動で続きから進む（毎回かどうか、**Worker のログに subrequest の
   エラーが出ないか**を見る。D1 の呼び出しが 50 回に数えられるかの実測になる）
6. 候補を選び、表示名・説明を直す。根拠リンクを開き、commit 固定のページが開く。
   表示名を空にすると送る前に止まる（41 文字以上も）
7. 同意の確認が出ている間は、候補・題名・フォルダの入力が触れない
8. 材料を 1 つ外して「候補を作り直す」→ 候補が変わり、**枠は減らない**。6 回目で上限の文面
9. 確定 → マップが開く。ノードの「理解すること」がリポジトリ固有になっている。ノードを選ぶと、
   右パネルの「根拠」に、種類（文書・コード・Issue）ごとの一覧が出る（ページの下には出ない）
10. 確定の途中でタブを閉じて開き直す → 下書きの一覧から続きから進められる。確定済みの下書きは一覧に出ない
11. 手で作ったマップを開く → 根拠の欄は出ない（エラーも出ない）
12. **下見のあとで URL を書き換える**: 下見したあとに URL の欄を別のリポジトリへ書き換える →
    下見の結果（対象フォルダ・「下書きを作る」）が消え、作成できない。もう一度確認すると、書き換えた先で出る
13. **下書きを 2 つ作って行き来する**: 別々のリポジトリで下書きを 2 つ作り、一覧から交互に開く →
    候補の選び方・直した表示名・題名・外す材料が、前に開いた下書きのものにならない
    （同じ画面のままブラウザの「戻る」「進む」で行き来しても同じ）
14. **同意の確認中は入力が止まる**: 同意の確認が出ている間は、候補・題名・フォルダ・ヒントを変えられない
    （確認の前の内容のまま確定される）
15. **説明の長さ**: 原文の名前がある候補で、説明を 200 文字ちょうどにする → 「原文の名前を含めて 200 文字まで」と
    送る前に止まる（サーバーの断りまで行かない）
16. **根拠が無いノード**: 確定したマップに、手でノードを足して選ぶ → 「リポジトリの根拠がありません」と出て、
    ほかのノードの根拠は出ない

#### 見やすさ・参考ファイルの指定・種類（#322）

17. **候補の画面**: 候補が 1 件 1〜2 行に畳まれている。「直す」を押した件だけ入力欄が開く。
    絞り込み・並べ替え（根拠が多い順）・「表示中を選ぶ／外す」が効き、選択中が `N / 30` で出る
    （31 個以上を選ぶと赤字で知らせ、確定できない）。確定のボタンが画面の下に付いてくる
18. **読んだ材料**: 文書・コード・Issue ごとに畳まれている（コードは閉じている）。「外す」で薄くなる。
    指定したファイルは「指定」の印が付き、「指定したファイル N 件・読んだ M 件」が出る
19. **参考ファイルを一覧から選ぶ**: 下見のあと、「ファイルの一覧から選ぶ」を開く → 絞り込み → チェックで入力欄に入る。
    5 個を超えて選べない。入力欄に `/docs/concepts.md`・`docs/Concepts.md`・存在しないパスを書く →
    先頭の `/` は取り除かれ、近い名前があれば「直す」が出て、無いパスは警告が出る
20. **種類**: 候補の行で種類を選び直せる（「種類なし」も）。確定したマップで、ノードが種類ごとに塗り分けられ、
    種類名のラベルが付く。凡例を押すと、その種類以外が薄くなる（もう一度押すと戻る）。
    理解度は枠線（確認済み=緑・学習中=橙）と ✓ で見分けられる。手で作ったマップ・言語別マップは今のまま
21. **右パネル**: 「学ぶこと」「確かめる」「つながり」「根拠」の順に区切られ、「理解すること」の値が無いものは
    `—` ではなく「未確認」と出る。言語別マップ（`/map/<言語>`）・ホーム・手で作ったマップでも同じ区切りで崩れない
22. **古い下書き**: この変更の前に候補まで進めた下書きを開く → 種類は「種類なし」で、そのまま確定できる
