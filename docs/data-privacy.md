# データとプライバシー

学習データの保存期間・削除・送信範囲・同意の正本。アーキテクチャ全体の方針は
[`docs/architecture.md`](architecture.md) を参照する。

ソースコード、選択範囲、質問文、診断メッセージには、業務上の機密情報や個人情報が
含まれうる。そのため保存対象を二段階に分ける。

- **既定で保存する**: Concept ID、言語、イベント種別、時刻、解決状況、必要最小限の診断コード
- **既定で保存しない**: コード本文、周辺コード、質問本文、AI回答全文

長期履歴やAI品質改善のために本文を保存する機能を提供するなら、目的・保存期間・削除方法を
明示したオプトインにする。ユーザーがデータをエクスポート・削除できるAPIも、同期機能と
同じ設計単位で検討する。

## 保存期間と削除

学習イベントは**無期限に保存する**。自動で消す期限は設けない。

- 学習イベントは習熟度を導出する正本である（docs/concepts.md「サーバー側の導出」）。
  期限で古いイベントを消すと、利用者が何もしていないのに習熟度が変わる。
- 保存するのは上の「既定で保存する」メタデータだけで、本文は含まない。
  期限を切ってまで減らすべき機微な内容は、そもそも保存していない。

その代わり、利用者がいつでも自分で取り出し・消せる経路を用意する（#79）。
「決めていない」ではなく「無期限、ただし本人がいつでも消せる」を方針とする。

| 操作         | API                              | 消える／返るもの                                     |
| ------------ | -------------------------------- | ---------------------------------------------------- |
| エクスポート | `GET /v1/learning-events:export` | 自分の学習イベント全件と、そこから導出した習熟度     |
| 履歴の削除   | `DELETE /v1/learning-events`     | 自分の学習イベント全件。アカウント・端末・設定は残す |
| 退会         | `DELETE /v1/me`                  | アカウントごと全データ（docs/auth.md §8）            |

- **エクスポートの形式は `packages/domain` の `LearnerProfile` そのものである。**
  VS Code 拡張が `globalState` に持つ形と同じで、独自形式を作らない。
  再取り込み（インポート）は未実装だが、形を揃えておけば後から足せる。
- **削除の粒度は全件だけにする。** 1件のイベントは複数の Concept にまたがる
  （`conceptIds` が配列）ため、「特定 Concept のイベントだけ消す」は
  同じイベントに乗っている別の Concept の根拠まで消してしまう。粒度を細かくするなら、
  イベント単位で消すのか、Concept ID だけを外すのかを先に決める必要がある。
- **習熟度は別途消さなくてよい。** サーバーは習熟度を保存せず、
  `GET /v1/learning-profile` のたびにイベントから導出する。イベントを消せば習熟度も消える。
  この性質は `apps/api/src/routes/learning-data.test.ts` が固定している。
  将来スナップショットを置くなら、削除時にそれも消すこと。
- **手動の習熟度上書き（`mastery_overrides`）とユーザー設定は消さない。**
  これらは利用者自身の宣言であり、行動の記録ではない。消したいときは個別に戻すか、退会する。
- **保存した確認問題（`concept_checks`）は消さず、エクスポートにも含めない（#185）。**
  生成の入力は Concept の定義だけで利用者個人の情報を含まないため、問題は全利用者で共有する
  静的コンテンツであり、学習データではない。`user_id` を持たず `users(id)` を参照しないので、
  退会（`DELETE /v1/me`）でも消えない。利用者の回答内容はここにも他のどこにも保存しない。
  正誤は `check_passed` / `check_failed` として Concept と結果だけを記録する（#43）。
- **消したイベント ID は記録に残さない。** 削除後に同じ ID を同期し直すと、
  新しい履歴として受理される。削除済み ID の一覧を持つと、それ自体が履歴の保持になる。
- **削除より前に受け取った同期は、書き込みが削除の後になっても残さない。**
  同期は受信時刻を決めてから D1 へ書くまでに I/O を挟むため、その隙間に削除が割り込みうる。
  削除した時刻を `learning_history_resets` に1つだけ記録し、同期の INSERT は
  受信時刻がそれ以前のイベントを書かない（同じ文の中で判定する）。
  そうしたイベントには「受理」を返す。受理したうえで削除に含まれた、という扱いである。
  記録は `users(id)` を `ON DELETE CASCADE` で参照するため、退会で一緒に消える。

### クライアント側に残るコピー

| クライアント | 学習データのコピー                                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| Web          | 持たない。KV にはセッションだけを置き、学習データは `cache-control: no-store` で中継するだけである。                                 |
| Desktop      | 持たない。OS の資格情報ストアにはトークンだけを置く（資格情報の破棄は Auth/08 #87 の範囲）。                                         |
| VS Code 拡張 | `globalState` に残る。`gakushuSochi.learnerProfile`・旧キー `codeCompanion.learnerProfile`・`gakushuSochi.explainedErrors` の3キー。 |

`globalState` のうち `gakushuSochi.clientId`（端末の識別子）、`gakushuSochi.consent`（同意の記録）、
`gakushuSochi.appliedHistoryResetAtMs`（同期状態）は学習データではなく、削除の対象外である。
SecretStorage の資格情報も同様（#87 が持つ）。

VS Code 拡張の `globalState` は、サーバーとは独立した手元の履歴である。サーバーだけ消して手元に残すと、
利用者から見て「削除した」ことにならない。そのため**削除の操作は両方を消す**方針とする。
`Gakushu Sochi: 学習データを削除する`（`gakushuSochi.deleteLearningData`）は
`DELETE /v1/learning-events` の成功を確かめてから `globalState` のコピーを消す。
順序をこの向きにするのは、サーバー側の削除が失敗したときに手元だけ消えて
「消えたように見える」状態を作らないためである（#124）。

削除を呼んだ端末以外のコピーは、同期応答に載せる `historyResetAtMs` で追従する。
`learning_history_resets` に記録した削除時刻を `POST /v1/learning-events:sync` の応答へ含め、
端末は前回より新しい時刻を受け取ったらローカルのコピーを消す（`appliedHistoryResetAtMs` が
適用済みの時刻を記憶する）。二度と同期しない端末に残る分は、その端末で削除コマンドを実行して消す。
両方の経路が要るのは、同期応答だけでは同期しない端末へ届かず、
コマンドだけでは削除を呼ばなかった端末のコピーが残るためである。

追従でコピーを消したあと、同期したばかりのイベントはローカルへ記録し直す。
削除の後にサーバーへ書かれているためである。ただし受信時刻が削除時刻以前で
「受理したが書かなかった」イベントは `results[].droppedByReset` で区別され、
サーバーにも残らないため記録し直さない。

なお拡張は、記録時に1件ずつ同期するだけで、`globalState` の履歴を後から再送しない。
サーバー側を消しても、手元のコピーからイベントが蘇ることはない。

## 何が誰へ送られるか

同意UI（#119）が利用者へ提示する内容の正本はこの節である。文面を変えるときはここを直し、
`packages/domain/src/consent.ts` の `CONSENT_NOTICE` を合わせる。

送信先は3つあり、**送るもの**と**保存されるもの**は一致しない。分けて読むこと。

### AI（`vscode.lm`、利用者自身の契約・API キー）

|                | 内容                                                                                                                                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 送るもの       | 選択したコード本文、周辺コード、選択範囲から参照した他ファイルの定義コード（最大3件、各最大5行）とファイルパス・シンボル名、選択範囲に重なる Diagnostics のメッセージ、質問本文、同じ Chat セッション内の会話履歴、言語ID、ファイル名 |
| 保存されるもの | 本プロダクトとしては保存しない。保存の有無は GitHub Copilot の規約に従う                                                                                                                                                              |

利用者の Copilot 契約を通るため、本プロダクトのサーバーを経由しない。
それでも**コード本文が端末の外へ出る**ことに変わりはなく、同意の対象である。

**送信先は Copilot とは限らない（#121）。** `selectChatModels()` を vendor で絞らないため、
利用者が VS Code へ登録した BYOK（Anthropic / OpenAI / Google など）やローカルモデルが
選ばれることがある。どれへ送られるかは利用者の VS Code の設定で決まる。
保存の有無はその提供元の規約に従う。同意の文面はこの事実を含む
（`CONSENT_NOTICE_VERSION` は 4。#121 で送信先が増えたため版を上げ、
#174 で Desktop / Web の経路を文面へ含めてさらに版を上げ、同意を取り直す）。

### API Server（Cloudflare Workers / D1）

|                | 内容                                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 送るもの       | Concept ID、言語ID、イベント種別、発生時刻、イベントID、セッションID、端末ID（`clientId`）、`Authorization: Bearer` の短命トークン |
| 保存されるもの | 上記のメタデータのみ                                                                                                               |

**コード本文・周辺コード・質問本文・AI回答全文は送らない。** 上の保存方針を
そのまま送信境界にも適用している。実装は
`apps/vscode-extension/src/learning/sync.ts`、契約は `apps/api/src/contract/learning-event.ts`。

### Managed AI（Gemini 経由、Desktop が使用）

Desktop アプリの質問機能が使う経路。`POST /v1/ai/responses` で API Server へ送り、
運営が契約する AI プロバイダ（Google Gemini）へ中継する。

|                | 内容                                                                     |
| -------------- | ------------------------------------------------------------------------ |
| 送るもの       | 選択したテキスト本文、質問本文、AI 応答の口調設定（persona）             |
| 保存されるもの | 本プロダクトとしては本文を保存しない。利用回数とトークン量だけを記録する |

コード本文が端末の外へ出るため、同意の対象である。Desktop 側の送信ゲートは
`apps/desktop/src/main/index.ts` の `askManagedAI`、サーバー側は
`apps/api/src/routes/ai.ts`。

### 同意を取るまで送らない

VS Code・Desktop・Web のどのクライアントも、上記の送信は**同意の記録があるときだけ**行う。
文面・版・記録の判定は `packages/domain/src/consent.ts` を共有する（#119、横展開は #174）。

共通の決まり:

- 記録は「同意した版」を持つ。文面が実質的に変わったら版を上げ、同意を取り直す。
- 読めない・壊れている・版が古い記録は**同意していない**として扱う。
- 取り消すと次の送信から止まる。**既に送ったデータは、同意の取り消しでは消えない。**
  消すには `DELETE /v1/learning-events`（「保存期間と削除」）を使う。
- 同意の記録は、利用者や開いたリポジトリから書き換えられない場所に置く（RULE-006）。

記録先と確認・取り消しの入口はクライアントごとに違う。

- **VS Code 拡張**: `globalState` の `gakushuSochi.consent`。設定項目にはしない。
  ワークスペース設定から書き換えられる場所に置くと、開いたリポジトリが同意を
  偽装できてしまう。取り消しはコマンド `Gakushu Sochi: 送信内容の同意を取り消す`。
- **Desktop**: メインプロセスが `userData` 直下の `consent.json` に記録する。
  renderer や `settings.json` の保存経路（`settings:save`）からは触れない。
  送信は Managed AI への POST の直前にメインプロセスで判定する。
  確認・取り消しは設定画面の「送信の同意」から。
- **Web**: Web Worker が Workers KV の `consent:{sub}` にユーザー単位で記録する。
  ブラウザ側（Cookie・localStorage）には置かない。`GET / PUT / DELETE /consent` が
  管理経路で、`PUT` は画面が提示した文面の版を送らせ、ずれていれば
  `409 consent_notice_outdated` で弾く。`/api/*` への書き込み（GET/HEAD/DELETE 以外）は
  Worker が同意を確認してからだけ API Server へ中継し、無ければ
  `403 consent_required` を返す。閲覧（GET/HEAD）と削除（DELETE）は同意が無くても使える。
  削除は「同意を取り消したあとにも使える別操作」なので、同意で止めると
  取り消した人が自分のデータを消せなくなる。
  確認・同意・取り消しは設定画面の「送信の同意」から。

送信の直前に出す `confirmSend`（ターミナル／クリップボード経由の本文プレビュー）は
これとは別物である。同意は「この製品が何を外へ出すか」への一度きりの合意、
`confirmSend` は「今回この本文を出してよいか」への都度の確認であり、両方を残す。
